# Source-only triage after the module boundary review

This memo orders the next **source-review and design work**. It does not rank production incidence or measured performance. B1–B26 remain in the [bug audit](04-bugs.md); the [roadmap](10-roadmap.md) owns the later measurement and pilot gates. Checked-out source has not generally been matched to the deployed image. No tests, production queries, or application changes are part of this pass.

| Order | Review unit and source evidence | Concrete source-only deliverable | Decision it enables |
| --- | --- | --- | --- |
| 1. Rights decision integrity | B26 drops the stream ID before selected item-route checks; B2 caches a decision without path and stream. The cached resolver has only a Zoomify tile caller in the reviewed source. Active criteria, configuration and deployed exposure are unknown. | A route-by-route rights-input table covering PID, path, stream, action, user, request context and cache key; identify every raw repository read after a rights check. | Define one authorization decision contract and cache scope before any public/rights split, proxy, or response cache. A possible incorrect allow is **policy-dependent**, not an observed incident. **2026-10-28:** B26 has no effect with the shipped criteria and B2 can only cause a false deny on the Zoomify route ([bug audit](04-bugs.md)); the decision-contract work remains a design prerequisite, not a fix. |
| 2. Repository mutation/recovery | B9 can swallow storage errors; B24 deletes a stream before recreating it; B20 deletes an object before replacement ingest. Each crosses FOXML, managed bytes and processing/search visibility. | One operation matrix for create/update/delete/thumbnail replacement: authoritative owner, durable step order, failure return, rollback or reconciliation, and index visibility. | Choose a single repository write contract and repair order. Treat these as a shared consistency problem rather than independent local patches. |
| 3. Process and indexing truth | B7 allows stranded claims; B25 permits late state reports to overwrite terminal state; B6/B8 affect worker availability and liveness judgment. B15 can hide per-document indexing failure while clearing its retry marker. | A process-state transition table with claim token/lease, permitted transitions, retry/fencing rules and per-document completion semantics. | Determine which manager/worker and indexing failures must be corrected before throughput tuning or a transport change. |
| 4. Search error fidelity | B11's exception-class mismatch is verified in deployed bytecode and maps sampled Solr HTTP 400s to API 500s. Why Solr returned 400 is unknown; other downtime incidents may exist. | A status/exception translation table for Solr 400, Solr 5xx and transport failures, plus a separate list of missing sanitized rejection evidence. | Scope the status-mapping fix separately from root-cause investigation and any Solr-versus-Elasticsearch decision. |
| 5. Bounded follow-up defects | B17 can deplete an Akubra unmarshaller pool on read failures. B18/B19 alter job/PUT outcomes; B10/B21–B23 affect folder count and transaction integrity; B16 affects log-proxy response lifetime/status. | Small, per-owner repair notes: trigger, invariant, affected callers, and later validation fixture. | Select focused fixes after the higher-risk contracts are specified; promote B17 sooner if read-failure frequency or pool pressure is established. |

The next source-only work item is the **rights-input table** because B2 and B26 can change authorization decisions and because the proposed rights/public boundary depends on its shape. Review every caller and active configuration visible in source; label a criterion or route unknown if deployment evidence is required. Follow with the repository operation matrix, then the process-state table. These three deliverables are suitable for review before the separate benchmarking environment is ready.

For architecture, define logical ownership first: curator owns collections, folders and UI configuration mutations; repository API owns trusted object/stream writes and secured reads; rights owns policy decisions and their freshness; processing owns claims and terminal state; public owns client/search/IIIF presentation. An optional rights proxy or rate limiter must preserve the same decision inputs and failure policy. The gateway already separates public and curator routes, but both use the same image; a five-service network split has no measured benefit yet. The [boundary maps](09-service-boundaries.md), [rights](20-rights-boundary.md), [repository](21-repository-boundary.md), [processing](22-processing-boundary.md), and [public](23-public-boundary.md) notes provide the source basis.

Performance remains an evidence gate, not a source-only conclusion. The IIIF access-log write, NFS reads, indexing batches, folder N+1 reads, FOXML/search-response caches, S3/zstd, and search-engine replacement are candidates with unknown stage costs or hit rates. The [benchmark handoff](19-benchmark-handoff.md) specifies later workloads and measurements for image opening, indexing and searching. A correctness fix may have no speed gain; no numerical gain is inferred here.
