# GitHub issues cross-check for the Kramerius bug inventory

## Method and limits

On 2026-10-28, I read the public GitHub REST issue lists for `ceskaexpedice/kramerius` (117 open, 1,072 closed), `ceskaexpedice/process-platform` (3 open, 6 closed), `ceskaexpedice/akubra` (3 open, 7 closed), and `ceskaexpedice/hazelcast-locks-server` (1 open, 2 closed). Counts exclude pull requests. I screened all titles, read the bodies of likely matches and bug reports, compared them with the bug entries that existed then, then added the seven verified reports GH1–GH7 below. I reread cited source lines at Kramerius `origin/master` (`560676c85d276bd53f2dbaae95e87ddc6abd6e07`), Akubra `51d821bcb55b89050e834ea00651aeb051146495`, and process-platform `976dc4b12c0592ba1ed0afea72558061619afa17`. The deployed image revisions are unknown. “Related” below means similar symptom or subsystem, **not** the same proven cause. An open GitHub issue alone is not proof that its bug persists in these revisions.

## Other open issues screened

- [Kramerius #1340](https://github.com/ceskaexpedice/kramerius/issues/1340) reports stale `reportedAction` thread-local state, with production evidence in the issue. The named `AbstractStatisticsAccessLog` at `origin/master@560676c` has no such field; the reported code belongs to a different revision, so it was not promoted from this pinned source.
- [Kramerius #1250](https://github.com/ceskaexpedice/kramerius/issues/1250) reports lost MODS `eventType`, but `OriginInfoDefinition.java:81–82@560676c` includes `@XmlAttribute(name = "eventType")`. That disproves the issue's proposed cause for this revision; another import path may still drop it.
- [Kramerius #1084](https://github.com/ceskaexpedice/kramerius/issues/1084) reports an illegal access to JDK-internal `XMLGregorianCalendarImpl`. The pinned `BaseConvertor.java:2149–2154@560676c` uses `DatatypeFactory`, so this reported cause is already absent.
- [Kramerius #1101](https://github.com/ceskaexpedice/kramerius/issues/1101) reports that a directory name containing spaces prevents process scheduling. The pinned admin API passes a JSON payload to the process manager (`ProcessResource.java:324–342@560676c`), and the pinned worker launches a `ProcessBuilder` from a `List<String>` (`PluginJvmLauncher.java:53–60@976dc4b`); the alleged whitespace splitting is not present on this path.
- [Kramerius #1176](https://github.com/ceskaexpedice/kramerius/issues/1176) reports an off-by-one PDF page index. The pinned `SolrInputBuilder.java:67–69,157–159@560676c` writes `page.index = pageNumber - 1` for virtual PDF pages; the reported `n+1` behavior is not established at this revision.
- [Kramerius #914](https://github.com/ceskaexpedice/kramerius/issues/914) reports that removing one of two DNNT licences did nothing. The pinned removal path calls `LicenseHelper.removeRelsExtRelationAfterNormalization` (`SetLicenseProcess.java:288–306@560676c`), whose lines 54–63 remove all matching occurrences while leaving other licence values alone. The reported failure may belong to an older path or a different cause.
- [Kramerius #1054](https://github.com/ceskaexpedice/kramerius/issues/1054) is related to BUG-003's successful-looking index job after skipped errors, but its reported missing page type is a separate input condition; no exact mapping is claimed.
- [Kramerius #1085](https://github.com/ceskaexpedice/kramerius/issues/1085) reports duplicate `licenses.facet` values and an inflated client count. The pinned schema copies three licence fields into one multivalued destination (`fields.xml:304–318@560676c`), so duplicate stored values are possible. The issue's reported facet-count inflation does not follow from that configuration alone; it needs a Solr response or client aggregation check before promotion.
- [Kramerius #1235](https://github.com/ceskaexpedice/kramerius/issues/1235) describes explicit RELS-EXT delete/create API operations failing to refresh the processing index. At pinned Akubra `51d821b`, `CoreRepositoryImpl.java:215–243` rebuilds relations on create and lines 283–291 delete them on stream removal. That reported missing-refresh path is absent at this revision; BUG-010 concerns a distinct failure during the rebuild.
- [Akubra #20](https://github.com/ceskaexpedice/akubra/issues/20) reports an empty `hasVolume` element after deleting a volume. The pinned `RelsExtHelperImpl.removeRelation` removes the selected element (`RelsExtHelperImpl.java:186–204@51d821b`), so this report needs the actual delete call path or affected revision to locate the cause.
- Remaining bug-like open reports without a confirmed pinned-source cause are tracked below. Their issue bodies alone were insufficient to promote a bug.
- [Akubra #21](https://github.com/ceskaexpedice/akubra/issues/21) is an ingest consistency/performance improvement; [#22](https://github.com/ceskaexpedice/akubra/issues/22) is a ProARc feature request. [Hazelcast locks server #1](https://github.com/ceskaexpedice/hazelcast-locks-server/issues/1) is a health-check operations proposal. None is a confirmed new code defect in this cross-check.
