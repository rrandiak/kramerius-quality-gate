# KB-011 — Public worker PDF generation disables the ALTO text layer

> **In one sentence:** PDFs generated by the public worker contain page images but no searchable ALTO text layer.

**GitHub issue verification:** this report checks [upstream issue #1338](https://github.com/ceskaexpedice/kramerius/issues/1338) against the pinned source; it is not an independent production discovery.

## Symptom

The upstream report observes that a public-worker PDF has scans without the expected text layer.

## Cause

`GenerateFullPDFServiceImpl.java:67–68@560676c85d276bd53f2dbaae95e87ddc6abd6e07` explicitly calls `documentService.setUseAlto(false)` before building the document. `DocumentServiceImpl.java:410–415@560676c85d276bd53f2dbaae95e87ddc6abd6e07` loads ALTO into an image page only when `isUseAlto()` is true, and `SimplePDFServiceImpl.java:195–204@560676c85d276bd53f2dbaae95e87ddc6abd6e07` passes it to the PDF template only when the page carries ALTO. The generated document therefore cannot carry ALTO text to the PDF renderer, even when the page has an `OCR_ALTO` stream.

## Evidence and frequency

Source-confirmed at the pinned revision. [Upstream issue #1338](https://github.com/ceskaexpedice/kramerius/issues/1338) reports an affected PDF; this review did not inspect document content or count affected MZK jobs.

## Impact

Readers cannot search, select, or copy text from these generated PDFs, and assistive text access is reduced.

## Fix

Enable ALTO for the public-worker document build when the configured PDF mode requests a text layer. Keep image-only generation as an explicit mode if it is needed.

## Test

Use an in-memory page with an ALTO fixture and render a PDF through the public-worker path. Assert that text extraction from the resulting PDF returns the fixture text.
